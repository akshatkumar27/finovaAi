# iOS shipping plan — 2026-09-14 (no Xcode locally)

**Constraint discovered:** the developer's Mac does not have Xcode installed. The original `ios-setup` skill assumed Xcode was available for pod install + signing + local `xcodebuild archive` and does not work here.

**Revised path:** cloud build via **EAS Build** (Expo Application Services). The developer's Mac only needs `node`, `npm`, and network access; everything Xcode does (pod install, signing, archive, TestFlight upload) runs on Expo's cloud-mac farm.

**New skill for a low-end model to execute:** `ios-eas-build`.
**Original Xcode-based skill kept as fallback:** `ios-setup` (labeled "requires Xcode locally").

---

## Cost delta

| Item | Xcode path | EAS path |
| --- | --- | --- |
| Local disk (Xcode) | ~40 GB | 0 |
| Apple Developer Program | $99/year | $99/year |
| Build service | free (local) | free tier: ~30 iOS builds/month; paid $19/month for unlimited |
| Signing cert management | manual, in Keychain | managed by EAS |
| Time to first TestFlight | ~1 day of hands-on Xcode work | ~30-60 min of orchestration + 5-15 min per build |

**Minimum to ship:** $99/year Apple + free EAS tier.

## Twelve-step plan (mapped to `ios-eas-build/SKILL.md`)

| # | Type | Step | Why |
| --- | --- | --- | --- |
| 0 | auto | node ≥ 18 check | eas-cli requirement |
| 1 | auto | `npm install -g eas-cli` | tool install |
| 2 | **human** | `eas login` (Expo account) | interactive password |
| 3 | auto | `npx install-expo-modules` | add Expo autolinking layer to bare RN — does NOT convert to Managed Expo |
| 4 | auto | Write `eas.json` (preview + production profiles) | build config |
| 5 | auto | Write `app.json` (bundle ID, name, version, icon path) | EAS metadata source |
| 6 | **human** | Enroll in Apple Developer Program; register bundle ID | one-time, off-machine |
| 7 | **human** | Generate app-specific password on appleid.apple.com | for `eas submit` — safer than primary password |
| 8 | auto | `eas build --platform ios --profile preview` | first cloud build; EAS interactively generates dist cert + provisioning profile |
| 9 | **human** | Wait 5-15 min for EAS build to finish | Apple queue |
| 10 | **human** | Download `GoogleService-Info.plist` from Firebase Console | Firebase iOS |
| 11 | auto | `eas submit --platform ios --profile production --latest` | send IPA to App Store Connect |
| 12 | **human** | (Optional) Upload APNs auth key to Firebase | for push in TestFlight |

Six automated steps + six human steps. Every human step has a verification the automated runner does after the human replies `done`.

## Two things still on the developer

1. **Apple Developer Program enrollment ($99/year).** No cloud build service can bypass this — Apple requires it for any code that reaches a device outside the simulator. First-time company enrollment can take 24-48h; individual accounts are usually same-day.
2. **Firebase Console downloads (GoogleService-Info.plist + APNs key upload).** These are Firebase Console UI actions that no automation can do without the developer's login.

Everything else is automatable end-to-end with `ios-eas-build`.

---

## What remains out of scope

- **Public App Store submission** — TestFlight only in this plan. Store submission needs metadata + screenshots + review answers.
- **Real-device install without TestFlight** (ad-hoc / development profile). Not covered.
- **CI-triggered EAS builds from GitHub Actions.** The manual `eas build` in Step 8 can be wrapped in a workflow; treat as a follow-up if the team wants push-triggered builds.

## Recommended path forward

1. Read `.claude/skills/ios-eas-build/README.md` — understand what the automated skill does.
2. Hand the skill to a small model per the README's hand-off prompt. Expect to be pinged for Steps 2, 6, 7, 9, 10, 12.
3. When TestFlight has a working build, decide separately whether to hand-off the final App Store submission to Fastlane or the App Store Connect UI.
